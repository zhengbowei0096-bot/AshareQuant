# 行情驱动研究模拟运行说明

## 已实现与边界

原有数据清洗、特征公式、预测系数、评分排名、训练验证、回测核心及正式准入均保留。新增执行层直接复用 `intraday_data`、`forecast.features_and_labels`、原研究仓位优化、`adaptive_policy`、`decision.costs` 和风险约束。日线模型对盘中未完成日线的推理不经过重新训练；属于分布不同、尚未独立验证的研究估计。概率复用原校准器；区间和参数不确定性沿用盘后估计，不能宣称盘中覆盖率已经验证。

- `intraday_inference.py`：读取已保存系数及对应数据版本，只使用当时可得历史和本轮未完成日线，保留推理输入、参数哈希和时间。原预测记录不变。
- `order_engine.py`：生成模拟限价委托；等待后续报价，处理部分/全部成交、撤销、拒单、资金保留、T+1和盈亏。
- `dynamic_service.py`：行情获取、模型/决策节奏、持久化事务、故障恢复、收盘结算、报告和手动账户差异核对。

真实券商接口仍未接通。`LiveBrokerUnavailable` 始终拒绝真实下单、撤单和同步；没有真实成交回报验收，因此不具备自动实盘能力。真实账户由用户手动操作，不能保证与模拟账户一致。

## 时间顺序和成交口径

请求完成后才确定决策时间。两源报价、交易所参考资料、已接收新闻及版本证据保存进账本。重复、倒序、超过45秒、未来报价、异常跳价、累计成交量回退以及缺少交易状态资料，禁止相关成交。买卖盘只是观察值，不证明排队可成交。

委托当轮不能成交；后续报价时间必须晚于委托提交时间，并至少间隔1秒。模拟最多使用可见一档量的1%，包含不利滑点，价格不能超过委托限价或触及涨跌停。最低佣金按同一委托累计成交金额计算，部分成交不重复收最低佣金；重新委托独立收费。120秒未完成撤销，同股300秒冷却后重新决策，未成交卖单资金不能用于买入。断线不回填错过的成交，恢复后从当前有效报价开始。

研究参数仍沿用个股22.5%、弱市总仓位45%、日换手45%，行业37.5%、中性/强市67.5%/90%；最大回撤15%、最低权益120000元风险退出线不放宽，无杠杆。风控线是触发条件，停牌或跌停时不能保证退出或限制实际损失。资讯缺失时不新增买入。模型缺失不阻挡独立集中度/风险减仓，但行情缺失仍阻挡成交。

## 账本与收益

从原动态账户的已结算状态迁移，保存完整迁移快照和哈希，不覆盖原冻结记录。原账户没有券商确认的买入成本，因此新阶段成本采用迁移估值，并标注 `MIGRATION_MARK_NOT_BROKER_COST`。这是本阶段盈亏，不是从真实买入以来的盈亏。

现金 = 起点现金 − 买入金额 − 买入费用 + 卖出金额 − 卖出费用。
买入费用计入持仓成本；卖出按移动平均成本结转已实现盈亏；未实现盈亏 = 带时间戳的估值金额 − 剩余阶段成本。净值 = 现金 + 持仓估值，且阶段净值变动必须等于已实现 + 未实现盈亏。当日收益以上次结算净值为基准。手续费已包含在净值中，不重复扣除；滑点包含在成交价中。缺少有效持仓报价时保留旧估值并明确标记过期。

`NAV.csv` 为每日结算；`FILLS.csv` 为明确标注的模拟成交；`ORDERS.csv` 为委托生命周期。交易记录不会因报告整理被重写。真实账户、回测与本模拟账本不相加。

## 配置与运行

`config/dynamic_config.example.json` 为非敏感模板，复制为项目根目录的 `dynamic_config.json`。默认关闭，实际启用还依赖现有 `intraday_config.json`、`adaptive_config.json`、研究配置、30只观察池、已有已结算动态账户、历史数据版本和当日交易参考资料。直接在空白仓库启用会明确失败，不自动虚构账户。

| 参数 | 默认 | 含义 |
|---|---:|---|
| refresh_seconds | 30 | 报价轮询间隔；不是供应商逐笔更新承诺 |
| model_refresh_seconds | 60 | 保存系数的研究推理间隔 |
| decision_cooldown_seconds | 300 | 同股新委托最短间隔 |
| order_ttl_seconds | 120 | 模拟委托失效时间 |
| minimum_latency_seconds | 1 | 撮合至少等待，仍必须是后续报价 |
| maximum_quote_jump | 0.05 | 相邻有效报价跳变保护 |
| real_orders_enabled | false | 只能为false；无真实通道 |

在项目根目录：

```sh
python -m asharequant.dynamic_service poll --root .
python -m asharequant.dynamic_service status --root .
python -m asharequant.dynamic_service close --root . --date YYYY-MM-DD
python -m unittest discover -s tests -p 'test_dynamic_execution.py' -v
```

本地 LaunchAgent 每30秒唤醒，按 Asia/Shanghai 交易日历及连续竞价时段决定工作。集合竞价、午休、休市只观察/撤销待撮合委托，不模拟集合竞价成交。参考资料服务与新闻服务沿用原配置。18点每日流程独立调用动态账本结算，即使模型研究失败也会尝试结算，结算失败保持失败状态。电脑必须开机、可运行且联网；休眠不会自动补造期间交易。

盘中提醒改由独立无声 Mac 弹窗服务发送，详见下文。

## 与手动真实账户核对

准备本地JSON（不提交仓库）：`{"asof":"带时区的实际时间","source":"USER_MANUAL","cash":0,"positions":{"股票代码":100}}`。替换成实际数据后：

```sh
python -m asharequant.dynamic_service reconcile --root . --snapshot path/to/manual.json
```

只生成 `reconciliation.json`，列出现金/股数差异；不自动改模拟账本，不把用户手填记录称为券商确认的成交或收益。

## 验证与恢复

测试用合成报价覆盖先委托后成交、部分成交费用、幂等/重启、断线、T+1、资金/费用、风险退出、收盘一次结算和未来数据截断。实际闭市连接检查不证明开盘服务或预测效果通过，首个真实交易时段还需检查交易状态覆盖、报价延迟、行情断流及订单流转。

变更前备份运行源码、配置与服务文件。恢复前先停止动态服务，保留其SQLite及WAL账本；恢复备份源码/配置/服务，核对账本日期，不回填停机交易。新执行代码或配置变化触发版本检查，不能无审核继续用旧账本。老账本仅作内部依赖及证据，默认报告只展示当前主账户。

规则核对依据：[上交所2026年修订交易规则及暂缓实施条文](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)、[深交所主板申报数量说明](https://investor.szse.cn/knowledge/t20230308_599142.html)。本模块仅支持原规则配置中的主板普通A股；不把创业板、科创板、北交所等制度混为一谈。具体当日涨跌停取交易证据，不写死所有证券10%。


## 无声 Mac 弹窗提醒
独立 `asharequant/mac_alerts.py` 每30秒读取动态模拟提醒与健康状态，不调用语言模型，不修改账本。仅服务异常及恢复触发无声对话框；模拟买入、卖出、成交、撤单/拒单不弹窗，仍保留报告与账本记录。委托与成交分别显示；同订单更新合并，超过5分钟注明历史。重复事件按ID抑制，连续两次研究推理异常才提醒；交易时段健康超过120秒未更新提醒一次，恢复再提醒一次。
对话框120秒后自动关闭；电脑须开机、用户登录且桌面可用，离线或休眠不能保证及时提醒。投递状态独立保存在 `logs/mac_alerts/`，失败重试；崩溃后可能重复提醒，不重复交易。系统接受弹窗不等于用户已经阅读。
启动：`python -m asharequant.mac_alerts --root .`。服务为 `com.asharequant.mac-alerts`，独立于行情、模型和18点每日分析；停用此服务仅停止本地弹窗。聊天轮询仅在弹窗人工确认后暂停，18点任务保留。
验证（2026-10-21）：7项通知逻辑测试通过，涵盖去重、部分成交数量、历史卖出、异常/恢复、持续异常、过期健康和无声调用；用户确认无声对话框可见。尚未用真实盘中买卖事件验收。回滚：停止本地提醒服务并恢复聊天轮询，交易算法及账本无须恢复。


盘中查看：桌面每日报告目录的“打开动态研究模拟.html”直接显示当前策略实时报告（30秒刷新）。独立 com.asharequant.report-mirror 服务每30秒同步展示副本及附件，无需跨目录跳转；每日导出保持相同展示。页面时间为原报告时间，同步不代表行情更新；同步失败保留旧内容并写入 logs/report_mirror_error.log。2026-10-21 修复旧入口空白，仅修改展示导航。

底部模拟成交、委托、每日收益和完整决策入口均为页内锚点：CSV记录转为可读表格，完整记录为中文字段表格及分层折叠明细，不依赖浏览器打开附件；没有记录明确显示缺项。原始CSV/JSON仍保存在运行报告目录，不更改账本。

2026-10-21 用户更新：关闭所有交易事件弹窗，仅保留异常及恢复提醒；聊天轮询保持暂停，18点分析不变。交易事件仍标记已处理，避免旧消息补发。

完整决策入口默认显示可读字段表格，不直接展示JSON代码；原始记录仍保留在运行目录供审计。


报告中文阅读层：reporting/plain_chinese.py 在每日导出与盘中展示时解释已知英文状态，将JSON/CSV链接转换为同目录中文HTML阅读视图，将代码块转为字段表格；保留原始记录。未识别字段保留名称供核查，不编造含义。每日导出检查本地目标和页内锚点；外部网站可用性不由本地校验保证。浏览器显示还需实际打开确认。


收益口径：系统只使用动态模拟主账户，持仓、委托、成交、费用和收益来自同一套账本。每日总览直接读取 `data/dynamic/account.sqlite3` 中经过完整性校验的已冻结收盘净值，不再读取券商净值导入表，不要求维护第二个账户。尚未结算的日期明确提示，不能以旧日收益替代。累计收益从本阶段迁移起点计算。模拟记账不代表券商确认的实际成交；用户自行操作资金账户，不自动保证一致。

## Execution fixes and upgrade review (执行修复与升级审核)

2026-10-23 修复两类执行衔接问题：

1. 权重换回股数时，浮点误差可能把数学上的整手股数变成略小的数，进而多减一手。委托与撮合现在共用 `intraday.target_shares`，仅纠正距离整手边界不超过四个ULP的噪声。最低资金、仓位、成交量、费用、T+1、委托寿命与风险阈值不变。
2. 日常数据刷新会创建新的版本标识；盘中推理应读取模型训练时绑定的不可变历史快照，不能要求它与最新指针相同。快照须属于相同股票/版本、两个CSV通过哈希校验、获取时间不晚于模型生成时间，模型生成时间不晚于决策时间。缺少旧版本不得回退到最新数据，仍暂停研究推理。原特征、训练、预测及校准公式不变。

报告委托表新增中文“状态原因”，解释为何等待、撤单或成交；原始事件和冻结账本不追改。`execution_code` 记录当前经过审核的执行源码指纹，`meta.code` 继续保留初始版本证据。

维护部署流程：停止本地动态轮询，确认每日流程锁空闲、账户已结算且无待撮合委托；备份源码、配置与SQLite一致性快照。运行完整测试及只读历史回放后，部署审核过的文件。由维护调用 `dynamic_service.approve_upgrade(root, expected_code, validation_sha, reason)`，其中 `expected_code` 为上一审核版本，`validation_sha` 为本次验证记录的SHA-256，`reason` 记录变更目的。该入口仅在休市、配置一致且账户已结算时追加 `execution_upgrades`；常规轮询不会自动调用它。核对账本与配置不变后再恢复服务。

回滚同样需要停服务和备份：恢复已保存源码后追加相应的回滚审核记录；若回滚到不支持审核链的旧程序，必须先核对它与初始指纹一致，并保留所有升级记录。不得通过改初始元数据、删除成交记录或回填成交来绕过版本检查。

这些修复不取消股票行情及公司行为校验。任一模型所需股票输入尚不可靠时，当前原有整组推理仍暂停，只保留独立风险检查；不能把回放测试通过描述为真实开盘验收通过。

## Per-slot research trials (分组研究试用)

The daily source may carry a different reviewed ridge recipe for each stock and prediction horizon. Intraday inference reads `model_features` from each daily forecast, falling back to the original common feature set for old records. It continues to reuse daily fitted parameters and does not retrain on each quote. A trial or daily prediction release does not validate unfinished daily bars or grant trading/probability admission. See [MODEL_UPGRADES.md](MODEL_UPGRADES.md).

## Dynamic decision diagnostics (动态判断异常与恢复)

“最近动态判断与原排名”现在直接解释为什么没有明细，包括最近盘中尝试时间、具体异常、判断覆盖数、最近成功时间及恢复确认时间。行情检查问题按股票列出。缺少完整判断时显示说明，不留下空表，也不把最近尝试时间冒充成功判断时间。

- **尚无记录**：尚未保存有效盘中尝试，等待交易时段运行。
- **判断受阻**：例如模型绑定历史不匹配、行情来源冲突、买卖盘无效或公司行动待核对。保留最后一次异常及时间；休市、服务重启和代码部署都不能自动清除它。独立风控减仓与估值仍受各自条件限制，不代表模型推理正常。
- **已恢复**：后续实际保存的一轮记录具备完整观察池的唯一股票判断、完整模型审计及合规时间顺序，且选中证据的校验值有效。显示最近一次异常之后首次成功的时间。后续再次失败立即回到受阻状态，不拿旧成功结果填表。
- **证据无法核验**：记录缺失字段、无法读取、时间不合规或校验失败时，不宣称已恢复。

休市显示的成功判断是历史记录，必须核对日期。判断成功不要求产生交易，也不等于独立模型验收通过。`report.json` 的 `decision_diagnostic` 是从既有证据派生的展示字段；原始周期、成交与净值记录不追改。当前健康日志仍表示服务本轮状态，不将历史异常冒充当前交易时段的新告警。桌面实时入口继续每30秒同步，未来每日导出沿用相同模板；没有开启交易提醒或恢复频繁聊天轮询。

下一开盘核验应在当地交易日历确认的交易日、北京时间09:30以后，检查连续至少3轮真实运行证据：请求耗时、报价年龄、观察池完整覆盖及质量问题、模型实际重算与1/5/20日结果、完整判断和恢复时间、模型/行情/订单/撮合的真实先后顺序，以及现金加持仓估值等于权益和盈亏恒等式。没有成交时撮合检查标不适用，不为验收强制交易。软件测试、历史只读诊断和开盘实际运行分别报告；有缺项就列明缺项。一次性核验需要电脑在线且应用运行，不会补造离线期间交易。

维护该展示涉及已绑定指纹的 `dynamic_service.py`，仍须遵循上文收盘备份和 `approve_upgrade` 追加审核流程；不得修改初始指纹或降低风控。回滚同样需要审核原版本并保留审计链，不能删除新增审核记录。
